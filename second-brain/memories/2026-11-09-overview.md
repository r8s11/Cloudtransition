## Playbook architecture (current state)
- [stated] Repository uses a two-layer system: an architecture layer (this chat — owns sequencing, spec cards, MANIFEST tracking, blueprint decisions) and an execution layer (a separate smaller-model session writing one module at a time from paste-ready spec cards, with AGENT-CONTRACT.md as its system prompt)
- [stated] Taxonomy: 11 numbered families — 00-meta, 10-day1-takeover, 20-hardware-lifecycle, 30-sop-engine, 40-saas-lifecycle, 50-tool-mappings, 60-people-lifecycle, 70-change-incident, 80-continuity-ops, 90-case-studies
- [stated] Five modules at FINAL status: 10.1, 20.1, 30.1, 40.1, 70.1
- [stated] Locked skeletons: Universal SOP Template (30.1) inherited by all procedure modules; canonical asset schema (20.1) as field dictionary for all hardware modules
- [stated] Notation rule: `[Token_Name]` = org-portability placeholder, must be declared in TOKENS.md before use; `<field>` = fill-in-at-use-time value, no declaration needed; anything in square brackets not in TOKENS.md is a defect
- [stated] Key governance files: TOKENS.md, STYLE-GUIDE.md, MODULE-SPEC-CARDS.md, ADOPTION-GUIDE.md, TAXONOMY.md, AGENT-CONTRACT.md
- [stated] CLAUDE.md was deleted after a security leak (it had published excluded employer names in a public repo); AGENT-CONTRACT.md is the sanitized replacement
- [stated] 60-people-lifecycle was built with three modules (role provisioning matrix, onboarding SOP, offboarding SOP) after being identified as a phantom family referenced in governance files but never built on disk
- [stated] 70-change-incident was renumbered from 60 to free the 60 range for people-lifecycle
