    Monitoring coverage

    What this view can—and cannot—establish from current sources.

      This console is read-only. It does not restart services, run commands, or collect credentials.

      Connections, definitions & local dashboard context
      PrometheusLoki readinessBeszel
      Usage
      Memory used = total − available. Volume used = size − space available to non-root users (Linux) or free space (Windows). Capacities use binary units. Windows system volume and Linux root filesystem are labelled separately.
      Sampling and clocks
      Current usage and network/IO rates use exported samples and five-minute rate windows. History is queried from Prometheus for the selected period. Source sample timestamps use Prometheus’s clock; collection time uses the dashboard clock. They may differ.
      Missing coverage
      No metric means unknown, not healthy or idle. A successful scrape is not a successful target probe. Docker log activity alone does not provide container CPU or memory. Host CPU/process counts cannot identify AI tasks, model-token usage, or costs.
      Log handling
      Messages are bounded and common credential patterns are redacted server-side. Avoid sending secrets to logs. Existing tailnet dashboard access also permits reading the monitoring data shown here.
