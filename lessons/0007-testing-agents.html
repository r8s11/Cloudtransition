Time: 6 minutes · Win: make a test fail if an agent unexpectedly requests a live model

Three layers to verify

  1. Tool test: give the function fake data or a fake HTTP client. Check the real permission rule.
    • Gmail: fake subprocess.run so it receives a separate argument list; assert no write tool is registered.
    • Smart home: fake the HTTP client; assert an unapproved entity or action is rejected before any request is sent.
    • NYC: fake the HTTP response; assert source_url and retrieved_at are present and missing evidence yields an explicit limitation.
  2. Agent test: replace the model with TestModel or FunctionModel. Use FunctionModel when a test must force a particular tool call or multi-step path deterministically. Never let a test point at a real mailbox or device.
  3. Live evaluation: only later, with explicit account access, data scope, and budget approval.

Pydantic AI documents agent overrides and local test models for avoiding real model cost, latency, and variability. Unit testing

Offline smoke test

import pytest
from pydantic_ai import models
from pydantic_ai.models.test import TestModel

models.ALLOW_MODEL_REQUESTS = False
pytestmark = pytest.mark.anyio

async def test_greeting_agent_runs_offline():
    with greeting_agent.override(model=TestModel()):
        result = await greeting_agent.run("Say hello.")
    assert isinstance(result.output, str)

This checks execution and output type, not answer quality. If the agent has tools, use fake dependencies. The test model can exercise tools; never let a test point at a real mailbox or device.

Test the security contract

  • Gmail: only archive search is registered; subprocess receives separate arguments; no write tool exists.
  • Home Assistant: an unapproved entity or action is rejected before the HTTP request.
  • NYC: results include the actual source and retrieval date; missing evidence produces an explicit limitation.
  • All agents: errors stay visible; empty results are not mislabeled as complete coverage.

Use a FunctionModel when a test must force a particular tool call or multi-step path. It lets the test define the model response deterministically.

Never in tests

  • Real keys, API credentials, or device tokens.
  • A real mailbox, live Gmail, or real email content.
  • A real smart-home device or physical action.
  • A live model endpoint or provider network call.

Offline tests first. Live tests require a separate, explicit decision.

Self-check

Why is a passing TestModel run not proof the Gmail agent is safe?

The test model does not prove real prompt resistance, provider data handling, archive freshness, OAuth scope, or access-control behavior. Test each boundary with fake services, then review live access separately.
