Time: 6 minutes · Win: leave with a staged plan for your first useful agent

Start as a local CLI

Keep the first version easy to inspect and stop. A small project can separate one agent, its adapters, and its tests:

personal-agents/
  src/personal_agents/
    gmail_reader.py
    home_control.py
    nyc_specialist.py
    services.py
  tests/
    test_gmail_reader.py
    test_home_control.py
    test_nyc_specialist.py
  pyproject.toml

Your existing CLI agent definitions are instructions consumed by other coding tools. A Pydantic AI agent is Python application code with a model, typed tools, and runtime dependencies. Reuse the useful job descriptions and safety rules; do not assume the definitions become executable Pydantic AI agents automatically.

Bound every run

Set request or token limits for runs, especially when one agent can delegate to another. Pydantic AI's multi-agent guide documents usage limits for avoiding runaway requests and costs.

Log timestamps, tool names, outcome, and safe error categories. Keep model/provider choice and secrets in configuration, not prompts.

Stage the rollout

  1. Build the test-model skeleton. Entry criterion: the agent runs offline with TestModel and no live requests are allowed.
  2. Use synthetic Gmail, device, and city fixtures. Entry criterion: every tool returns bounded, fake evidence; nothing touches a real source.
  3. Test permissions and failure behavior. Entry criterion: tests fail if an unapproved tool, entity, or query is requested.
  4. Review model-provider data handling and cost. Entry criterion: you can state exactly what leaves the computer and what it costs.
  5. Only then request access to a real source or device. Entry criterion: explicit account access, data scope, and budget approval are on record.
  6. Add one specialist at a time; measure whether it answers with traceable evidence. Entry criterion: each new specialist passes its normal, missing-source, and boundary tests.

Your first build target

Start with the Gmail archive reader: its access is already read-only, local search is available, and it has no physical side effects. Begin with synthetic snippets, then decide separately whether a hosted model may receive actual snippets. Keep smart-home control disabled until you identify the exact device API or bridge.

Self-check

What must be true before adding a new specialist?

Its job, trusted sources, narrow tools, denied abilities, structured result, and failure cases are explicit. Tests prove those boundaries with fake services.

The source list is curated in RESOURCES.md.

Ask your teacher any follow-up question. Do not authorize live credentials, device actions, or data transfers until you choose that step explicitly.
