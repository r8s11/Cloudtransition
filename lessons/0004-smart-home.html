Time: 8 minutes · Win: understand the control boundary before connecting a device

First verify the path

Amazon's Smart Home Skill API lets Alexa call a device provider's skill to control devices that provider exposes. The docs do not establish a general API for an agent to command every device already linked to your Alexa account. Amazon's Smart Home Skills overview

A direct agent path can use a vendor API or a bridge such as Home Assistant—but only if it already controls the target. Home Assistant documents its REST service-call API and its Alexa integration separately. REST API · Alexa integration

Stop condition: if the device is Alexa-only and no supported API or bridge controls it, do not invent an integration. Identify the exact device and the supported API first. Small lab: one light, two actions

This example assumes Home Assistant already controls light.study_light. Keep the entity fixed in code. The model may choose only on or off.

from dataclasses import dataclass
from typing import Literal

import httpx
from pydantic_ai import Agent, RunContext

@dataclass
class HomeServices:
    client: httpx.AsyncClient
    base_url: str
    token: str

home_agent = Agent(
    "openai:gpt-6.1-sol",
    deps_type=HomeServices,
    instructions="Control only the study light when explicitly asked.",
)

@home_agent.tool
async def set_study_light(
    ctx: RunContext[HomeServices],
    action: Literal["on", "off"],
) -> str:
    """Turn the pre-approved study light on or off."""
    service = "turn_on" if action == "on" else "turn_off"
    response = await ctx.deps.client.post(
        f"{ctx.deps.base_url}/api/services/light/{service}",
        headers={"Authorization": f"Bearer {ctx.deps.token}"},
        json={"entity_id": "light.study_light"},
    )
    response.raise_for_status()
    return f"Home Assistant accepted the {action} request ({response.status_code})."

Read the token from a protected environment or secret store, not source control. Keep the configured Home Assistant URL outside model input. After the call, verify reported state if the user needs confirmation; an accepted service call is not proof the physical light changed.

The tool allow-list narrows what the model can request; it does not narrow the Home Assistant token's own authority. Protect that token like a powerful credential.

Approval boundary

Start with a lamp. Add an application-level confirmation before any higher-impact action. A model saying “confirmed” is not user approval — only the user can approve. Do not expose locks, alarms, garage doors, or arbitrary entity IDs in the first version. An accepted service call is also not proof the physical device changed; verify reported state if the user needs confirmation.

Sandbox: control the study light (approval required)

Fixed entity: light.study_light. Actions: on / off only. The model may choose the action, but it cannot pick an arbitrary entity — and it cannot approve the action itself.

Self-check

Why is the entity ID fixed in the function?

It turns the function into an allow-listed capability. The model can select a bounded action, but it cannot redirect the credential to another entity by inventing an ID.
