Time: 5 minutes · Win: distinguish the agent loop from the model provider

The model

A Pydantic AI Agent is the typed boundary between your Python app and a model. It can hold instructions, tools, dependency types, and an output type. Your Python app still owns data access and permissions. Pydantic's agent guide

Start without a network call. The built-in test model lets you exercise an agent offline. TestModel reference

from pydantic_ai import Agent
from pydantic_ai.models.test import TestModel

helper = Agent(
    "test",
    instructions="You are a private-work assistant. Be concise.",
)

result = helper.run_sync(
    "What can this agent do?",
    model=TestModel(),
)
print(result.output)

This verifies the framework can run; it does not prove a real model understands the instruction. A live provider is a separate step.

What Pydantic AI actually adds

Plain model clientPydantic AI Agent
You write the prompt, parse the reply, and hope the shape is right. A typed boundary: instructions, tools, dependency types, and an output type, all validated by the framework.
The model can suggest anything; your code must guess what it meant. The model proposes a tool call with typed arguments; your application decides whether the tool exists, validates arguments, and enforces permission.
No built-in structure for running tools or handing results back. A run loop: model → tool call → tool result → model → answer, owned by your Python app.

Install when ready

uv init personal-agents
cd personal-agents
uv add pydantic-ai

Then configure a supported provider and model using the current Pydantic AI provider documentation. Never paste a key into source, a lesson, or chat. A hosted model also means the prompt and tool results are sent to that provider.

Keep the first job small. “Search my local Gmail archive for a phrase and summarize matching snippets” is a better first target than “manage my life.”

First-job checklist:

  • One data source you already control and can read.
  • One action the model may request, nothing more.
  • Read-only by default; no send, delete, or modify until a separate approval step exists.
  • A fake dependency for testing before any live model or API call.

Self-check

Which parts belong to your Python application, not the model: Gmail permission, tool code, and deciding whether a source is trustworthy?

Check your answer

All three. The model can suggest a tool call. Your code decides whether the tool exists, validates its arguments, enforces permission, and judges the returned evidence.
