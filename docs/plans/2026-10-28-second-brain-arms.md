# Second Brain and ARMS implementation plan

## Scope and decisions

Implement the supplied Second Brain guide and adapt all twelve ARMS levels to the existing Cloudtransition workspace. The user explicitly requested autonomous completion, so infer workflow from existing sources instead of conducting the guides' optional interviews. Preserve all source documents and existing applications. Do not install third-party daemons, alter accounts, send messages, enable paid background model calls, or enable cache pings. The guide explicitly requests a real comparison: use the existing authenticated Claude CLI for at most four technical-only fresh-session benchmark calls, each capped at $0.50 API-equivalent usage.

Existing structure: root CLAUDE.md and OPERATIONS/CODE/MONEY/LEARNING/HEALTH routers; FastAPI dashboard; visual-second-brain; agentic-os TypeScript mission runtime and an unrelated in-memory Python domain package. Keep these intact. Operational source of truth is TASKS.md, DASHBOARD.md, routine.md. Exclude employer-private data, secrets, vendored code, generated files and agent instruction files from content ingestion.

## Components and contracts

1. `second-brain/brain.py`: Python standard-library deterministic CLI, importable using importlib. Root argument for temporary-fixture verification. `index`, `query QUESTION`, `remember --title TITLE --summary SUMMARY --body BODY`, `check`, `benchmark`. JSON command output. `query` returns question, evidence list (path, start_line, end_line, text), files_opened, elapsed_ms and explicit no-match/stale status. Index metadata scores candidates without opening them; one selected source and at most one safe local pointer. Plain Markdown memories and compact single catalogue. Atomic writes and writer locking. No model calls. No copying whole workspace documents into memory. Benchmark real queries and clearly label byte/token proxies, not fabricated Claude /context costs.
2. `tools/arms/routines.py`: read-only local routine inventory, session usage analysis and repeated-work suggestions; deterministic passive checks; explicit zero model spend; persisted local reports. No modification of existing OS schedules. Suggested routines never execute arbitrary session text. Detect missing usage data honestly. Produce JSON with `inventory`, `usage`, `suggestions`, and `checks` for the app. Offer a local schedule for deterministic checks only where safe; actual installation must be distinguished from available configuration.
3. `tools/arms/app.py` and static assets: loopback-only local review micro app with durable feedback and a recommendation selection cart. Standard library HTTP, strict Host/Origin/JSON boundaries, no shell execution. App reads routine report and invokes memory CLI only via fixed argument arrays. Search, remember, park feedback, copy selected recommendations/comments. Feedback applies only by explicit later approval; no silent skill rewriting. `tools/arms/clipper/`: one-job unpacked browser extension, user-invoked article metadata/selected-text capture exported as Markdown. No background browsing or broad host access.
4. Managed skills: workspace knowledge routing, note capture, calibrate review, and HTML-first artifacts with existing brand tokens. Only managed-skill tool may create skills. Never modify user-authored skills. Reference existing routers and concrete CLI commands, no invented personal facts.
5. Root routing additions and `second-brain/README.md`, `tools/arms/README.md`: exact commands, source-project tradeoffs, all twelve levels classified, privacy/safety boundaries, verified measurements and unmet external prerequisites.
