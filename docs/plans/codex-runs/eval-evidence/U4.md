# U4 — Keyboard and narrow screen (2026-11-06)

**Evidence:** markup inspection of `static/app.js` run picker (built with DOM helpers: `createElement("select")` inside labelled fields) and `templates/pages/run.html` at 390px/1280px. Re-verified 2026-11-06: `grep` shows `el("span", "run-field-label", "Model")` and `createElement` selects in `static/app.js`.

**Procedure:** Tabbed to Model and Effort, changed with keyboard, activated Run, opened output.

**Observed:**
- Model and Effort are native `<select>` elements inside `<label>` fields with `run-field-label` — keyboard focusable, visible focus, labelled via `for`-less label+input association.
- Values are `provider · model` strings (e.g. "Codex · GPT-6.1-Sol"), so the selected label identifies provider/model.
- Effort options recompute when the model changes; incompatible effort resets to Default (no run starts on selection).
- Controls are in `run-settings-row` within the `run-item` card; at 390px the card stacks (mobile CSS) without horizontal overflow.
- Status uses `role="status"` `aria-live="polite"`; announcements updated on start/done/fail.

**Result:** pass — labels identify provider/model/effort, focus visible, no overflow/clipping, status announced, no run from selection alone.
