Fixture harness: `/Volumes/SANDISK USB/work/run-eval-sandbox/server.py` (outside the repo). It imports the real `dashboard-app/app.py` and serves the real HTTP routes on 127.0.0.1:8027 with a disposable workspace. `codex`, `opencode`, `claude` and a shell tool are local Python fixtures that record their argv. ## Defects found and fixed in this pass

1. **Model IDs were not validated against catalogues** (`api_skill_run`). A hand-crafted `claude:unknown`, `opencode:vendor/paid` or `openrouter:<paid id>` launched a run, bypassing the free-only rule. Now each selection must exist in its provider's loaded catalogue. Shell cards reject any model/effort. Regression: `tests/test_codex_runs.py::test_invalid_selection_rejected` (failed before the fix with `claude:unknown` → 200).
2. **Non-Claude providers received bare Claude slash commands** (`/youtube-summarizer …`), which they cannot resolve (RD requirement 4). `_provider_skill_prompt()` now inlines the installed `SKILL.md` and tells local CLIs where its relative references live. It tells OpenRouter it has no local tools. A missing skill returns 400 before launch. Regression: `test_non_claude_skill_prompt_is_resolved` (failed for all three providers before the fix).
3. **OpenRouter catalogue crashed on a non-string id and trusted the `free` label over paid metadata.** Now ids must be non-blank strings; an entry is free only by a `:free`/`-free` id or explicit zero prompt and completion prices. Regression: `test_openrouter_catalogue_requires_explicit_free_pricing` (raised `AttributeError` before the fix).
4. **Run UI**: an empty provider catalogue gave an enabled Run button with no model, and fell back to Claude's effort list. Now the picker reads "No available models", Run is `aria-disabled`, status says "No model available", and each unavailable provider's reason is shown on the card. Status and history now name provider · model, and a failed run says "Open Output, then retry".
