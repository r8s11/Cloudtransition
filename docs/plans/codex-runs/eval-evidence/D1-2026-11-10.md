Compared the rendered Run tab with the mockup's Default and Mobile sections after the Command Center refinement.

Screenshots in this folder: `D1-run-1440.png` (implementation, 1440x1000 viewport, full page), `D1-run-390.png` (implementation, 390x844 viewport, full page), `D1-mockup-1440.png` (mockup, all sections).

## Preserved

- Paper faces on the vermilion ground; Inter for titles and body, JetBrains Mono for field labels and status.
- Model and Effort are native `<select>` elements inside labelled fields on every configurable card.
- No horizontal scroll: document overflow measured 0px at 1440, 1280, 1200, 1100, 1000, 901, 768 and 390px wide.
- At 390px: 14 selects, none past the right edge; smallest select and smallest Run button are both 44px tall; no tag leaves its card.

## Differences from the mockup

Introduced by the refinement on 2026-11-10, approved by Roosevelt in that session:

- Three sections in place of one card list: "Local tools" first, "Model and API runs" second, "Dashboard design runs" collapsed third. UI/UX review and Polish sit in the third.
- Each card carries a tag beside its title stating what it spends: "No model · $0", "Jev API · paid", or "Model · …".
- The masthead reads "Command Center" and the tabs sit in four groups.

Already present before the refinement:

- Run is a filled vermilion button; the mockup draws it as a paper button.
- The catalogue refresh control is "Refresh models" in the section header, not "Update models" beside Run.
- The line under Run reads "Ready", not the mockup's "Codex · GPT-6.1-Sol · Default effort".
- OpenCode and OpenRouter offer Default effort only; the mockup's mobile example shows "High". The requirements document makes Default-only the rule.
- At 1440px the grid fits three cards per row, so Model and Effort stack inside each card. They sit side by side at 1280px, where two cards fit.

**Result:** pass — the design system and labelled native selectors are preserved, controls wrap without horizontal scroll, and every difference is listed above.
