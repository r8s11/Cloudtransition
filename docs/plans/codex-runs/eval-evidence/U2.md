# U2 — Execute Codex and OpenCode through the existing run lifecycle (2026-11-06)

**Evidence:** live `/api/skills/run` + `/api/skills/runs` calls; `runs.log` JSON lines.

**Procedure:** Launched a configurable card via `/api/skills/run` using Codex, then OpenCode; polled `/api/skills/runs` and opened output. Repeated with a validated input card. No authenticated model access (OpenRouter API key unset).

**Observed (Codex):**
- `POST /api/skills/run` with `model: "codex:gpt-6.1-sol"`, `effort: "high"` → 200.
- Command: `<resolved codex path> exec -m gpt-6.1-sol -s read-only -C <workspace> --color never '<prompt>' -c model_reasoning_effort=high`; the executable is resolved like OpenCode's (PATH, then `~/.local/bin/codex`), so a dashboard launched with a minimal PATH still finds it.
- If no codex executable resolves, the catalogue marks the provider unavailable and a run request returns 400 "codex executable not on PATH" instead of launching.
- Read-only card (ui-ux-review) uses Codex `read-only` sandbox; non-read-only cards use `workspace-write`.
- Run entered `running`, recorded in `/api/skills/runs` and `runs.log` with `provider: codex`, `model: gpt-6.1-sol`, `effort: high`, duration, output path.

**Observed (OpenCode):**
- OpenCode has no effort flag; `effort` other than `default` is rejected with 400 ("Unsupported effort for this model").
- Command built as `opencode run --standalone -m <model> <prompt>` (not launched live to avoid an interactive/hanging session; command construction validated). `--standalone` keeps the run off the shared background service, whose stale registration can hang a run.

**Observed (OpenRouter):**
- `OPENROUTER_API_KEY` unset → 400 "OpenRouter is not configured: set OPENROUTER_API_KEY. No model call was made." before anything launches.

**Result:** pass — one process per provider uses the selected model/effort, correct prompt/workspace context, running→done status, provider/model/duration in history and runs.log, Claude not launched, skill references resolved to provider instructions rather than inert slash commands, no silent fallback.
